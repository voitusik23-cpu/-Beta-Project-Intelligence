# TASK 06 — Monitoring, shortlist and acceptance run

Приоритет: P2 | Выполнять после TASK 05

## Цель
Обеспечить регулярное обновление возможностей и подготовить доказательный shortlist без искусственного заполнения ТОП.

## Monitoring
1. Проверить существующий scheduler/worker и надёжность его запуска.
2. Для каждого проекта хранить last_checked, next_check (если применимо), last_change и stale status.
3. Отслеживать изменения: campaign open/closed, waitlist availability, testnet/points status, deadline, docs, GitHub activity, funding/team announcements и source health.
4. Не создавать новый сигнал на каждую повторную публикацию одного факта; связывать обновление с историей проекта.
5. При изменении существенного факта пересматривать соответствующие evidence, confidence и при необходимости score.
6. Уведомления — только о значимых изменениях, с источником и кратким объяснением.
7. Добавить защиту от чрезмерной частоты запросов, rate limits, повторных уведомлений и сбоев.
8. Сохранить журнал успешных и неуспешных проверок.

## Acceptance run
- Снять snapshot всей базы и текущих статусов.
- Прогнать Level 1 по всему доступному пулу с причинами решения.
- Выполнить Level 2 deep research для наиболее сильных кандидатов, если объём доказательств достаточен.
- Подготовить shortlist примерно 20–50 проектов только если качество подтверждает такое количество; меньше — допустимо.
- Разделить MY TOP PROJECTS, EARLY INCUBATION, WAITLIST, FUNDED PROJECTS, TESTNET & POINTS, LATE ENTRY, WATCHLIST и REJECTED/ARCHIVED.
- Для каждого кандидата указать score, confidence, условия участия, затраты, ограничения, дедлайн, источники и last checked.
- Составить отчёт: что подтверждено, что не удалось проверить, какие источники не работают, какие проекты требуют ручного решения.

## Безопасность и ограничения
- Никаких обещаний наград/дохода.
- Никакой автоматической регистрации, wallet connection, signatures, transactions, KYC или обхода ограничений.
- Никакого искусственного заполнения ТОП.
- Не удалять архив и историю сигналов.
