# Product Roadmap — Beta Project Intelligence

Версия: 1.0 | 2026-11-02

## Принцип реализации
Сначала доказать корректность существующих данных и безопасно стабилизировать приложение. Затем улучшать discovery, research, scoring и monitoring. Не запускать все этапы одновременно.

## Этапы и gates

| Этап | Результат | Условие перехода |
|---|---|---|
| 0. Baseline | Зафиксированы рабочая копия, БД, git status, тесты и резервная копия | Данные и состояние приложения можно восстановить |
| 1. UI + data visibility | Единая тёмная дизайн-система; реальные счётчики, архив и постраничная загрузка | Выполнено в рабочей ветке 2026-11-04; тесты и визуальная проверка указаны в отчёте |
| 2. Source registry | Проверены все зарегистрированные источники, health, ошибки и ограничения | Для каждого источника известны статус, способ получения, last success и причина отказа |
| 3. Discovery pipeline | Надёжный сбор сигналов, нормализация, дедупликация, очередь и повторный запуск | Повторный запуск не создаёт дубли; сбои не теряют прогресс |
| 4. Deep research | Исследование команды, финансирования, продукта, технологий и репутации | Каждый существенный факт имеет источник, дату и уровень доверия |
| 5. Dossiers + ranking | Полные русскоязычные досье, Opportunity Score и Evidence Confidence | Рейтинг воспроизводим, причины оценки видны, слабые доказательства не маскируются |
| 6. Monitoring | Регулярное обновление статусов, дедлайнов, источников и изменений | История изменений сохраняется; stale data заметны |
| 7. Acceptance run | Полный проход по пулу, shortlist и отчёт | ТОП формируется только из подтверждённых кандидатов; количество не форсируется |

## Очерёдность
- P0: TASK 01 — UI, аудит данных и исправление dashboard (выполнено; ожидает коммита/проверки push).
- P1: TASK 02 — Source Registry и интеграции.
- P1: TASK 03 — Discovery pipeline, дедупликация и resumability.
- P1: TASK 04 — Deep research и доказательная база.
- P1: TASK 05 — Досье, scoring и confidence.
- P2: TASK 06 — Monitoring и итоговый acceptance run.

Каждая задача выполняется отдельно в безопасной ветке/PR. Следующая задача не должна обходить незакрытые критические дефекты предыдущей.

## Неприкосновенные решения
- Не менять веса scoring без отдельного согласования.
- Не удалять базу, проекты и историю сканирования.
- Не выдавать наличие URL за подключённую интеграцию.
- Не создавать фиктивные данные и не обещать airdrop/доход.
- Не выполнять wallet connection, signatures или transactions автоматически.
- Не обходить CAPTCHA, KYC, geo/account limits, anti-Sybil или правила платформ.

## Критерии качества продукта
1. Русский интерфейс и выводы; названия проектов/компаний — оригинальные.
2. Кликабельные официальные ссылки.
3. Факты отделены от предположений и неизвестного.
4. У каждого существенного факта — источник и дата проверки.
5. Opportunity Score отделён от Evidence Confidence.
6. Никакого принудительного заполнения ТОП слабым материалом.
7. Устаревшие данные и недоступные источники видны пользователю.
