# TASK 03 — Discovery pipeline, deduplication and resumability

Приоритет: P1 | Выполнять после TASK 02

## Цель
Сделать сбор и обработку сигналов предсказуемыми, повторяемыми и восстанавливаемыми после сбоев.

## Шаги
1. Зафиксировать текущий путь данных: source → raw signal → normalized candidate → project identity → review queue/archive.
2. Проверить схему идентификации проекта: canonical domain, official social links, chain/ecosystem, contract/repository identifiers и aliases. Не объединять проекты только по похожим названиям.
3. Разделить raw signals и canonical project records; сохранять происхождение каждого сигнала.
4. Реализовать/проверить дедупликацию с объяснимым решением: exact match, strong match, possible duplicate, distinct.
5. Сохранять причину принятия, отклонения, архивирования и отправки на ручную проверку.
6. Обеспечить checkpoint/resume: после рестарта не терять уже обработанные элементы и не создавать повторные записи.
7. Добавить идемпотентность повторного импорта одного и того же источника/периода.
8. Обеспечить retry/backoff и dead-letter/error queue для устойчиво падающих элементов.
9. Проверить временные метки, часовые пояса, canonical URLs, redirect handling и изменение URL проекта.
10. Добавить тесты на дубли, похожие имена, конфликтующие источники, повторный импорт, частичный сбой и restart.

## Требуемый результат
- Документированная схема pipeline и статусов.
- Проверенная дедупликация с причинами решений.
- Повторный запуск безопасен и не портит историю.
- Метрики: discovered, normalized, duplicate, rejected, review, archived, failed, retried.
- Отчёт с тестами и примерами реальных записей без секретов.

## Ограничения
Не удалять исторические сигналы и проекты. Не выполнять массовое слияние/удаление записей без backup и отдельного подтверждения. Не менять утверждённые веса scoring.
