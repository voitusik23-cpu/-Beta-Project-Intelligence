# TASK 01 — UI redesign and data visibility

Приоритет: P0 | Статус: READY | Исполнитель: Codex

## Цель
Доработать существующее приложение Beta Project Intelligence в его текущей рабочей директории. Не создавать новую реализацию приложения в этом control repository.

## A. Предварительный аудит
1. Убедиться, что открыт именно проект Beta Project Intelligence.
2. Зафиксировать путь рабочей директории, текущую ветку и git status.
3. Найти README, master implementation report, архитектурные заметки и инструкции.
4. Проверить UI, frontend stack, CSS/theme tokens, шрифты и способ запуска.
5. Проверить схему БД и источник данных dashboard без изменения данных.
6. Снять baseline: главная страница, меню, список проектов, карточка/досье, источники и настройки.
7. Сделать безопасную резервную копию/контрольную точку.
8. Не выводить секреты в отчёт и не добавлять их в Git.

Если рабочая копия недоступна — не имитировать аудит и не создавать фальшивое приложение. Запросить открытие правильной директории.

## B. Визуальное направление
- Очень тёмный графитово-синий / near-black фон.
- Панели и карточки на 1–2 тона светлее фона, заметно отделены от него.
- Тонкие границы, контролируемые тени, достаточное внутреннее пространство.
- Один акцентный цвет: electric lime ИЛИ cyan, выбрать по логотипу; дополнительные цвета — только семантические статусы.
- Акцент для активной навигации, primary actions и ключевых индикаторов.
- Inter / Geist / IBM Plex Sans или качественный аналог; локальный шрифт или безопасный fallback без обязательного сетевого запроса.
- Повысить читаемость мелких подписей; не уменьшать текст чрезмерно.
- Убрать визуальную разрозненность и декоративный шум.
- Сохранить русскую локализацию и текущую информационную архитектуру.
Не делать кричащий neon/cyberpunk. Нужен дорогой, спокойный, профессиональный вид.

## C. Проверить все экраны
Sidebar/navigation; live radar/dashboard; new projects; early stages; testnet & points; opportunities; waitlist; funded projects; late entry; monitoring; my recommendations; review queue; favorites; archived/rejected; project dossier; source registry/health; settings; таблицы, фильтры, поиск, формы, модальные окна, badges, empty/loading/error states.

Не скрывать существующие возможности и не ломать навигацию.

## D. Критический дефект данных
По отчёту Codex на 2026-11-02:
- 291 проект прошёл первичный разбор;
- 26 карточек очереди созданы;
- dashboard показывает пустые/нулевые счётчики;
- лента сигналов пуста;
- из 12 источников фактически подключены 3.

Проверить, где хранится число 291 и 26 карточек; источник истины; источник counts/feed; API/SQL; соответствие полей и статусов; JS/HTTP/backend/CORS/serialization/async ошибки; фильтры и даты; loading/empty/error states.

Исправлять только после выявления root cause. Не вставлять hardcoded 291/26 и не создавать фиктивные карточки. Если БД не содержит нужных записей — объяснить расхождение с прежним отчётом.

## E. Ограничения
- Не менять scoring/weights и критерии отбора.
- Не менять pipeline, источники и бизнес-логику ради визуального эффекта.
- Не мигрировать БД без обоснования, backup и rollback.
- Не удалять файлы/данные и не затрагивать другие репозитории.
- Не выполнять push в неизвестный репозиторий приложения.
- Не переносить базу/секреты в этот control repository.

## F. Тестирование
Запустить unit/integration tests, lint/typecheck/build, Python compile/tests если применимо, JavaScript checks и ручную проверку основных экранов. Проверить desktop и узкую ширину/mobile: переполнение, обрезанный текст, читаемость статусов, кликабельность.

## G. Отчёт
Указать изменённые файлы; выбранные цвета/шрифты; baseline и after screenshots; root cause пустых счётчиков/ленты; исправления; команды тестов и exit codes; неподключённые источники; риски и rollback.

Не писать «готово» без доказательств. Завершить TASK 01, затем ждать технической приёмки перед изменением бизнес-логики.
